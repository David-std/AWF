# ADR-0036 — Smoke-test neural adaptation without unauthorized corpus training

- **Date:** 2026-10-21. **Status:** provisional S4 engineering prototype, stacked on draft PR #43.
- **Goal:** move from Ollama inference on an unmodified pretrained model to a concrete PEFT LoRA training pipeline, while preserving scientific validity, source permissions and the independent checker boundary.
- **Decision:** allow ONLY a small explicitly synthetic, SHA-pinned, group-separated local developer fixture to enter `ml-smoke`. No ordinary `TRAIN_ALLOWED` label, uploaded manuscript, historic AWS text or purported independent gold can enable this path. Require explicit `--allow-synthetic-training`; default is no-GPU dry-run. Base model is allowlisted, version-pinned to `Qwen/Qwen2.5-0.5B-Instruct@7ae557604adf67be50417f59c2c2f167def9a775`, and limited to 20 steps and short sequences; LoRA trains `q_proj/v_proj`, completion-only loss. GPU dependencies are optional; outputs stay ignored and local, with hashes and `promotion=DENIED`.
- **Why PEFT/TRL:** train small adapters rather than full dense weights on 6GB VRAM; use maintained library APIs rather than reinventing backpropagation, optimizer or tokenizer behavior. No assumption that QLoRA 7B fits on this GPU.
- **Reject:** SFT on 184 AWS requirements (not paired training examples, unknown rights), default Hugging Face auto-push, unbounded hyperparameter search, detector-score tuning as primary objective, shared train/eval groups, and treating the smoke evaluation split as independent scientific validation.
- **Tradeoff:** the locally-authored synthetic-only data flag is still self-described. The implementation cannot confer copyright permissions. This controlled smoke runs under user-local developer experimentation, **never** as a general rights gate or model registry promotion. Production data training stays blocked pending ADR-0028 external rights validation and human-adjudicated source gold.
- **Evidence:** Hugging Face TRL SFTTrainer and PEFT LoRA docs, Qwen model card. A successful unit test only validates the data/CLI path; actual adapter weights must be observed from a completed CUDA run before claiming neural fine-tuning occurred.
